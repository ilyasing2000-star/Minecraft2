# Auto BlockHit — Forge 1.8.9

Автоматический блок мечом. Блок ставится **заранее, до чужого удара**, а не после
своего. Всё делается через состояние клавиши, ни одного пакета мод не шлёт.

## Сборка через GitHub Actions

Самый простой путь — ничего устанавливать не надо.

1. Создай публичный репозиторий на GitHub.
2. Залей туда содержимое этой папки (вместе с `.github`).
3. Вкладка **Actions** → сборка запустится сама.
4. Внизу страницы сборки артефакт `autoblockhit-jar` — это готовый мод.

Первая сборка идёт минут пятнадцать: `setupDecompWorkspace` качает Forge и MCP
и декомпилирует майнкрафт. Следующие — пару минут из кеша.

## Сборка локально

Нужны **JDK 8** и **Gradle 2.14.1**. На более новых версиях ForgeGradle 2.0.2 падает.

```
gradle setupDecompWorkspace
gradle build
```

Готовый jar лежит в `build/libs/`. Кидается в `.minecraft/mods`.

Если хочешь `gradlew` вместо глобального Gradle — скопируй файлы `gradlew`,
`gradlew.bat` и `gradle/wrapper/gradle-wrapper.jar` из официального MDK 1.8.9.
`gradle-wrapper.properties` с нужной версией уже здесь лежит.

## Команды

| Команда | Что делает |
|---|---|
| `/bh on` · `off` · `toggle` | включить или выключить |
| `/bh status` | текущие настройки и статистика |
| `/bh smart <true\|false>` | блок только при игроке рядом |
| `/bh range <1-10>` | радиус угрозы в блоках |
| `/bh fov <10-360>` | конус взгляда противника |
| `/bh hold <0-100>` | тиков удержания после ухода угрозы |
| `/bh sword <true\|false>` | требовать меч в руке |
| `/bh unblock <true\|false>` | снимать блок на свой удар |
| `/bh skipblock <true\|false>` | не блокировать, глядя на блок |
| `/bh notify <true\|false>` | сообщения в чат |
| `/bh save` | сохранить в конфиг |

Алиас: `/blockhit`. Клавиша переключения — `B`, меняется в Управлении.
Конфиг: `config/autoblockhit.cfg`.

## Как это работает

Блок — это **состояние по умолчанию**, а не реакция. Пока рядом есть чужой игрок
в радиусе удара и повёрнутый к тебе, блок уже стоит. Значит, к моменту его удара
урон уже делится пополам.

По анимации замаха реагировать бессмысленно: `S0BPacketAnimation` приходит уже после
того, как сервер посчитал урон. Поэтому используется предсказание по геометрии
(дистанция плюс разворот), а не реакция на событие.

На свой удар блок снимается и тут же возвращается — внутри одного тика:

1. `ClientTickEvent.START` — решаем и ставим блок
2. `MouseEvent` в цикле `Mouse.next()` — снимаем
3. `while (keyBindAttack.isPressed()) clickMouse()` — удар уходит
4. `ClientTickEvent.END` — ставим обратно

Из опрашивающего потока DLL такой порядок был недостижим: там фронт нажатия
виден уже после того, как удар обработан.

## Важно

В 1.8.9 блок мечом замедляет движение и снимает спринт — это механика игры,
а не ошибка мода. Умный режим как раз и нужен, чтобы не ходить так постоянно.

Автоматический блок нарушает правила большинства публичных серверов,
а блок, появляющийся ровно при входе врага в радиус, статистически очень заметен.
